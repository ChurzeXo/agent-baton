Why Multi-Agent Systems Fail Without Baton

Autonomous coding agents are brilliant at typing code, but catastrophic at self-governance. Baton replaces naive conversational agreements with hard invariants.

PITFALL

Hallucinated Completions

✗ Fake Receipts

Agent reports: "Refactored authentication, updated 14 modules, all 42 tests passing." In reality, zero files were modified on disk. Naive orchestrators accept the claim and merge.

🛡️ Baton Guarantee: Requires verifiable Git commit SHA (git cat-file -e) & non-empty file modifications.
PITFALL

Sycophancy & Priming Bias

✗ Biased Reviews

Reviewer Agent reads the author's internal reasoning and rationalizations ("I skipped the corner cases because of XYZ"), leading to polite rubber-stamping.

🙈 Baton Guarantee: Double-Blind Sanitizer (--blind) strips CoT & excuses. Reviewer sees only pure requirements & code diff.
PITFALL

Self-Signing Loopholes

✗ Self-Approval

A single session toggles its environment variable or agent prompt, reviews its own output, and signs its own completion ticket without independent oversight.

🔐 Baton Guarantee: Ephemeral challenge nonces generated during forward are wiped upon verification. Cross-lane self-signing is cryptographically blocked.
PITFALL

Token Drain & Polling Burn

✗ Burnout Loops

Waiting for peer agent tasks using fixed polling intervals consumes thousands of LLM tokens, wastes battery life, and hammers developer machines.

⚡ Baton Guarantee: Kernel-level fs.watch event sleep. Zero tokens consumed during waiting; auto wakes up upon ticket status flip.

The Deterministic 4-Step Lifecycle

Every task advances through a strict, finite state machine: Draft → Forwarded → Received → Closed.

STEP 01

Create Ticket

baton new audit task "Auth Spec"

Author lane documents invariants, boundary tests, and expected Git evidence.

STEP 02

Double-Blind Transfer

baton forward <id> --blind --wait

Sanitizes subjective CoT, issues challenge Nonce, and sleeps with zero Token burn.

STEP 03

Independent Review

baton receipt <id> --nonce ...

Auditor executes shell commands in terminal and signs receipt with valid Nonce.

STEP 04

Reactive Acceptance

baton accept <id> -n "Verified"

Author wakes up instantly upon file event, runs preflight verification, and closes.
