一条协议链路，四个可验证阶段

THE INTERNALS OF AGENT BATON · 运行态全景图。从契约声明到实证回执，每一步都有机器可核验的物理边界。

PROTOCOL CORE · LIVE FLOW RUNNING

01

CALLER LANE

发起端 · 契约声明

POST /handoffs/new
  • Task Specification
    定义客观机器判据与修改边界，拒绝模糊自然语言
  • baton new <lane> <type>
    自动落盘 Markdown 票据，注入前后置事实源
  • Double-Blind (--blind)
    物理脱敏 <thinking> 思维链，杜绝顺从偏见
02

ZERO-TRUST GATEWAY

零信任网关与事件中枢

OS fs.watch · 0-Token Sleeping
  • Audit Nonce
    派单时签发高熵一次性随机令牌，强制审计回执核销，拦截同一会话自导自演自签。
  • 0-Token 探针
    baton forward --wait 挂载内核文件事件，发起端静默休眠，零 Token 消耗零发热。
  • Evidence 判据菱形
    运行 git cat-file -e 核验真实 Commit SHA 与变动文件；虚假回执直接硬拦截拒收！
03

WORKER LANE

执行工作台 · 独立实测

Work Queue
  • 直取角色待办
    过滤并认领归属当前 Lane 的任务单 baton status --for
  • 终端独立实测
    严禁信口开河自报，以终端命令运行结果为准
  • 提交代码生成 SHA
    产生不可伪造的真实 Git Commit
04

CLOSED & VERIFIED

无损交付闭环

200 OK Callback
  • 真实证据回执单
    附带 Commit、变更文件路径与 Audit Nonce
  • 毫秒响应式自动唤醒
    底层探测回执就绪，发起方会话自动苏醒
  • 一键复核合入
    核对验收标准，状态翻转为 Closed 归档

02 / Why a protocol

拒绝人肉传话！为什么多 Agent 协同必须像调 API？

单兵写代码容易，多智能体协同极难。传统聊天式多 Agent 系统在生产中频频崩溃的 4 大死穴与 Baton 工业防线：

拒绝上下文衰减与传话失真

人工在窗口间复制粘贴 Prompt，不仅繁琐，更会导致信息漏损、思维链污染及顺从偏见（Sycophancy）。Baton 以单一事实源 Markdown 契约穿透单体或微服务边界，无损直达。

✓ 规范单一源 · 阻断思维链污染

杜绝假装改完与幻觉回执

传统框架经常采信 Agent 的自报（“我已测试通过”），实则根本没改文件。Baton 建立实证主义物理门禁，强制核验磁盘真实修改与 git cat-file -e 提交，无证据直接拒收。

✓ git cat-file -e · 物理级实据拦截

杜绝同一主体自审自签

同一个会话自封审计角色，自己给自己盖章通过？Baton 在派发审查时动态签发一次性密码学挑战令牌 (Audit Nonce)，回执必须核销 Nonce，硬性阻断本地会话自签漏洞。

✓ Audit Nonce · 防自导自演自签

事件驱动待机，告别发烫与 Token 浪费

不用跑 while 轮询耗尽上下文。baton forward --daemon 借助操作系统内核级 fs.watch 事件总线，等待期间 0 CPU、0 Token 开销，回执到达秒级自动唤醒。

✓ 0-Token 睡眠 · 内核级毫秒唤醒
03 / Workflow

日常使用：像调用 API 一样极简的 4 个动作

Request → Async Sleep → Response → Callback，自然流畅

01

发起调用 (POST /request)

明确声明目标角色与机器验收判据

SHELL
baton new audit task "重构鉴权模块并补充单元测试"
02

异步挂起待机 (Async Sleep)

双盲脱敏思维链，签发 Nonce，0 Token 待机

SHELL
baton forward <ID> --daemon --blind
03

提交实证回执 (200 OK + Proof)

审查方独立实测，附带 Git 提交物理证据

SHELL
baton receipt <ID> --evidence-paths "..." --audit-nonce "..."
04

事件回调自动唤醒 (Callback Wakeup)

发起方秒级苏醒，验收合入归档

SHELL
baton accept <ID> -n "全量实测通过，闭环合入"
04 / Topology

全场景灵活拓扑：仓内职责制衡 & 跨微服务中枢

无论单个代码仓库还是庞大多微服务集群，一条命令完成脚手架初始化

MODE 01 · INTRA-REPO

单一仓库内以 Lane 隔离角色职责

在现有仓库内生成 .handoffs/ 子 Hub，实现实现方（impl）、审计方（audit）与架构方（arch）分工制衡。

SHELL
baton init --lanes impl,audit,arch
MODE 02 · CROSS-REPO HUB

中立中心调度统筹多个独立微服务

建立独立中枢 Hub，统一调度 api、web、docs 等不同微服务代码仓库之间的跨仓任务交接。

SHELL
baton init --cross --targets api,web,docs
支持 baton status --mermaid 一键输出实时任务拓扑流向图。 PURE CONFIG · ZERO-HARDCODE
