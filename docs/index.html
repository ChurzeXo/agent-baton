交接状态探针：怎么让 AI 自动闭环？

无需你在多个 AI 窗口间人肉复制粘贴，更不跑死循环发烫。

探针模式: 0-Token 事件驱动监听
CPU: 0.0% Token: 0
Step 01 / 发起交接

交代任务并挂起探针，AI 进入“静音休眠”

发起方 AI 交代好修改目标后，执行转递命令。探针立即在后台挂起，等待期间不耗电脑性能、不耗 Token。

💤
# 发起交接并进入后台监听探针（一条命令搞定）
$ baton forward audit-20261105-01-task --wait
→ 已生成接单提示词，供直接转递接收方
→ 探针已就绪：正在后台静音待机...（0 Token 开销）
Step 02 / 真实改动门禁

拒绝“口头改完”！接收方必须携带真实 Commit 与改动文件

接收方 AI 施工完毕后提交回执。系统底层会物理检查 Git 提交历史和真实文件，嘴上说改了但没动代码的直接打回！

🔍
# 接收方提交回执（必须带真实提交哈希与修改路径）
$ baton receipt audit-20261105-01-task \
--evidence-paths "src/auth.ts,tests/auth.test.ts" \
--evidence-commits "a1b2c3d" \
-n "## 结论\n已在终端独立运行测试，全部通过。"
✅ 检查通过：Commit a1b2c3d 真实有效，回执已登记！
Step 03 / 探针毫秒自动唤醒

回执一落盘，探针立刻 Exit 0，发起方 AI 自动醒来收尾！

底层基于操作系统的文件事件通知（fs.watch）。当真实回执保存的瞬间，休眠的发起方立刻被唤醒，自动完成闭环验收。

⚡
🎉 [探针感知] 检测到 audit-20261105-01-task 真实回执已落地！
⚡ 发起方 AI 会话被自动唤醒（退出码 0），开始验收：
$ baton check && baton accept audit-20261105-01-task -n "已复核代码改动，验收合入！"
🏁 任务顺利闭环！全程无需人工传话。
💡 核心价值：不信嘴说、不耗待机 Token、自动唤醒闭环。

用 Baton 写代码，体验有什么不同？

普通开发者用 AI 协作时最容易踩的坑，一次性解决

🛡️

杜绝假装改完

以前 AI 经常嘴上说“已经修好”，实际上根本没动文件。Baton 强制查验 Git Commit，没写真实代码休想交差。

💤

静默待机不耗电

不用死循环轮询，笔记本不再发烫。探针启动后 AI 彻底静默，等待期间零 CPU 占用、零 Token 浪费。

⚡

自动唤醒不用人肉搬运

接收方写完回执的一瞬间，发起方自动被操作系统唤醒继续干活，从此告别来回切换窗口复制提示词的繁琐。

日常使用只有 4 步

简单好记，不需要死记硬背复杂配置

1
创建任务单
告诉 AI 要实现什么、验收目标是什么
baton new impl task "重构登录接口"
2
转递并启动探针
生成接单提示词，发起方自动静默待机
baton forward <ID> --wait
3
接收方提交真实证据
写完代码后，带 Git commit 和修改路径交卷
baton receipt <ID> --evidence-paths "..."
4
自动唤醒并闭环
发起方自动苏醒，确认改动无误后关闭任务
baton accept <ID> -n "验收通过"
